# Agent Playbook — Test Generation

**Agent ID:** `test-generation-agent`
**Version:** 1.0
**Trigger:** Azure DevOps story moves to "In Progress" OR a feature branch is created matching `feature/*` or `bugfix/*`
**Mode:** `observe` | `act`

---

## Purpose

Automatically scaffold tests for a story before the developer starts coding, so tests are written from the requirements — not retrofitted afterward. The agent:

1. Reads the story's acceptance criteria from Azure DevOps
2. Identifies which layers need tests (UI, API, integration, E2E)
3. Generates **test file scaffolds** with describe blocks, test names, and AAA structure — but intentionally leaves implementation as `TODO` for the developer to complete
4. Commits the scaffold files to the feature branch and opens a draft PR (or posts the files as a comment in `observe` mode)
5. Links the generated test files back to the ADO story

## Agent Instructions

### Step 1 — Parse Acceptance Criteria into Test Cases

Read every acceptance criterion. For each one, extract:

- **Scenario name** — a short, descriptive name (used as the `it(...)` / `[Fact]` description)
- **Preconditions** (the "Given" clause) — what state must exist before the test
- **Action** (the "When" clause) — what the user or system does
- **Expected outcome** (the "Then" clause) — what should be observable after the action
- **Test type** — classify as: `unit`, `integration`, or `e2e`

Classification rules:

| Criterion involves... | Test type |
|---|---|
| A single function, hook, or component in isolation | `unit` |
| Multiple layers (e.g., API endpoint + service + DB) | `integration` |
| User journeys spanning UI → API → DB | `e2e` |
| Negative / error handling within a single unit | `unit` |

---

## Outputs

### In `observe` mode

Post a PR comment (or ADO comment) containing:
- The generated test scaffold files as code blocks
- The test coverage mapping table
- Instructions for the developer on completing the TODOs

### In `act` mode

1. Checkout the feature branch
2. Write scaffold files to disk in the appropriate directories
3. `git commit -m "test: scaffold tests for #{{workItemId}} {{title}} [skip ci]"`
4. `git push` to the feature branch
5. Post ADO comment with the test coverage map and a link to the commit

---

## Escalation Rules

Escalate (post comment + Teams notification) if:

- Acceptance criteria could not be parsed into test cases (too ambiguous)
- Story has `security` tag and no tests cover the authentication/authorisation path
- The feature branch does not exist in the repository
- More than **15 test cases** would be generated — the story is likely too large and should be split
- Any git or ADO API call fails
